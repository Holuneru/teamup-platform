# TeamUp — обзор проекта

**TeamUp** — веб-платформа для студентов, которые ищут команду для стартапов, хакатонов, учебных и исследовательских проектов. Платформа объединяет профили с навыками, проекты, заявки и приглашения, рекомендации участников, каталоги хакатонов и наставников, личные диалоги и рабочее пространство проекта.

## Реализованные возможности

### Аккаунты и профиль

- регистрация и вход по email и паролю;
- JWT-аутентификация, пароли хранятся как BCrypt-хеши;
- профиль: имя, фамилия, университет, курс, описание, Telegram, GitHub;
- загрузка аватара;
- формат участия `ONLINE` / `OFFLINE` / `BOTH`;
- статус «Ищу команду» (`lookingForTeam`);
- управление навыками.

### Поиск людей

- список пользователей с фильтрами по университету, навыку, роли и формату участия;
- поиск по строке;
- рекомендации участников для проекта по совпадению требуемых навыков и статусу поиска команды.

### Проекты

- создание, редактирование и удаление проектов;
- список всех проектов с поиском и фильтром по навыку;
- собственные проекты владельца и проекты, где пользователь участник;
- карточка проекта, команда и рабочее пространство;
- выход из проекта и исключение участника владельцем;
- удаление проекта вместе с участниками, сообщениями, задачами и комментариями.

### Заявки и приглашения

- подача заявки на проект;
- просмотр заявок владельцем, принятие и отклонение;
- приглашение пользователя владельцем проекта;
- принятие и отклонение приглашений;
- предотвращение дублирующего членства;
- согласование статусов: принятие заявки закрывает ожидающее приглашение, принятие приглашения закрывает ожидающую заявку.

### Рабочее пространство проекта

- обзор проекта и команда;
- общий чат проекта с историей;
- упоминания участников через `@` и уведомления только упомянутым;
- Kanban-доска: колонки, исполнитель, приоритет, срок, drag-and-drop и смена статуса;
- редактирование задачи, комментарии к задаче;
- уведомления о назначении, смене статуса, комментариях и упоминаниях.

### Каталоги

- хакатоны с фильтрами по формату и дате;
- наставники с навыками и контактами.

### Личные сообщения

- диалоги между пользователями;
- непрочитанные сообщения и счётчик;
- скрытие диалога только для текущего пользователя без удаления истории у собеседника.

## Технологический стек

### Backend

- Java 21
- Spring Boot 3.5.16
- Spring Web, Spring Security
- Spring Data JPA / Hibernate
- PostgreSQL
- Flyway
- JWT (JJWT 0.12.6)
- Maven, Lombok

### Frontend

- React 18
- Vite
- React Router
- Axios
- Context API
- lucide-react
- CSS

## Архитектура

```text
HTTP Controller
    ↓
Service (бизнес-логика)
    ↓
Repository (доступ к данным)
    ↓
PostgreSQL
```

Для внешнего API используются DTO из `com.teamup.dto.request` и `com.teamup.dto.response`; JPA-сущности напрямую не сериализуются.

## Структура проекта

### Backend

```text
src/main/java/com/teamup/
├── controller/   REST-контроллеры
├── service/      бизнес-логика
├── repository/   Spring Data репозитории
├── entity/       JPA-сущности
├── dto/          request/response контракты
├── mapper/       преобразование entity ↔ DTO
├── security/     JWT и Spring Security
├── config/       конфигурация
├── exception/    исключения и единый формат ошибок
└── enums/        enum-типы
```

### Frontend

```text
frontend/src/
├── pages/        страницы приложения
├── components/   переиспользуемые компоненты
├── context/      UserContext, FeedbackContext
├── api/          Axios-клиенты
└── styles/       CSS
```

## Настройка окружения

Для локальной разработки переменные окружения не нужны. `src/main/resources/application.yaml` уже содержит локальные значения:

- JDBC URL: `jdbc:postgresql://localhost:5432/` (база по умолчанию пользователя `postgres`);
- пользователь PostgreSQL: `postgres`;
- пароль PostgreSQL и JWT-секрет: локальные значения в `application.yaml`.

JWT-секрет должен быть не короче 32 байт. Эти значения предназначены только для локальной разработки. Перед публикацией репозитория или деплоем замените пароль и секрет и вынесите их из отслеживаемого файла.

Если нужно переопределить значения без изменения `application.yaml`, скопируйте `src/main/resources/application-local.yaml.example` в `application-local.yaml`, заполните его и запустите с профилем `local`:

```powershell
$env:SPRING_PROFILES_ACTIVE="local"
```

`application-local.yaml` добавлен в `.gitignore`.

## Локальный запуск

Требуются JDK 21, PostgreSQL и Node.js, совместимый с версией Vite проекта.

1. Убедитесь, что PostgreSQL запущен и доступен с локальными параметрами из `application.yaml`. При необходимости измените их.
2. Запустите backend из корня:

   ```bash
   ./mvnw spring-boot:run
   ```

   В Windows: `mvnw.cmd spring-boot:run`.
3. Запустите frontend:

   ```bash
   cd frontend
   npm install
   npm run dev
   ```

Frontend по умолчанию работает на `http://localhost:5173`. CORS на backend разрешает этот origin.

## Проверки

```bash
./mvnw test
cd frontend
npm run build
npm run lint
```

Тесты backend используют H2 в режиме PostgreSQL и отключают Flyway через профиль `test`. Миграции в `src/main/resources/db/migration` рассчитаны на PostgreSQL.
