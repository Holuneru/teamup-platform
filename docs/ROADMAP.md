# Roadmap TeamUp

Roadmap разделяет уже найденную в коде функциональность и следующие инженерные этапы. «Реализовано в коде» не означает «проверено автоматическими тестами»: покрытие тестами оценивается отдельно.

## Этап 1 — текущие функциональные области

- [x] Регистрация и вход через JWT.
- [x] Получение и редактирование собственного профиля.
- [x] Загрузка аватара.
- [x] Каталог навыков и обновление навыков пользователя.
- [x] Список пользователей, фильтры и текстовый поиск.
- [x] CRUD проектов и поиск/фильтрация проектов.
- [x] Список собственных проектов и проектов, в которых пользователь участвует.
- [x] Заявки на вступление в проект: подача, просмотр, принятие, отклонение и удаление.
- [x] Приглашения в проект: создание, просмотр, принятие и отклонение.
- [x] Список участников и выход из проекта.
- [x] Рекомендации участников для проекта.
- [x] Каталог хакатонов и фильтры по формату/дате.
- [x] Каталог наставников и их навыков.

## Этап 2 — стабилизация и проверяемость (приоритет)

1. [ ] Обновить и сверить документацию API и модели данных с исходниками.
2. [ ] Добавить unit-тесты сервисов: регистрация, профиль, навыки, проекты, заявки, приглашения, рекомендации, хакатоны и наставники.
3. [ ] Добавить MVC/API-тесты для основных happy path и ошибок.
4. [ ] Проверить авторизацию и права доступа для всех операций чтения/изменения.
5. [ ] Проверить frontend-сценарии и согласованность контрактов Axios с backend DTO.
6. [ ] Исправить расхождения между `Project.members` и сущностью `ProjectMember`, если аудит подтвердит дублирование логики.
7. [ ] Убрать секреты из конфигурации и использовать безопасную конфигурацию окружения.
8. [ ] Настроить надёжное управление схемой БД через миграции.

## Этап 3 — качество пользовательского опыта

- [ ] Единая обработка ошибок API и понятные сообщения интерфейса.
- [ ] Состояния загрузки, пустого результата и ошибки на всех страницах.
- [ ] Проверка валидации форм на frontend и backend.
- [ ] Улучшение фильтрации и сортировки каталога проектов/хакатонов.
- [ ] Проверка адаптивности интерфейса и доступности элементов управления.

## Этап 4 — расширения после стабилизации

- [ ] Уведомления о заявках и приглашениях.
- [ ] Избранные проекты и хакатоны.
- [ ] Расширенные рекомендации с объяснением совпадений.
- [ ] Отзывы и рейтинг после определения правил модерации.
- [ ] Интеграция с Telegram — после определения конкретного пользовательского сценария.
- [ ] Чат и мобильное приложение — только после оценки потребности и архитектуры.

## Правило приоритета

Сначала безопасность, корректность данных и автоматические тесты. Новые пользовательские функции добавляются после того, как существующие сценарии можно надёжно проверить.
