# Рабочий список задач TeamUp

Статусы отражают наличие реализации в исходниках, а не гарантированный уровень качества. Функции, помеченные `[x]`, нужно будет дополнительно покрыть тестами на этапе стабилизации.

## Этап 1. Документация

- [x] Обновить обзор проекта.
- [x] Сверить REST API с mapping-аннотациями контроллеров.
- [x] Сверить сущности с JPA-моделью.
- [x] Обновить правила для Cursor и разработчиков.
- [x] Отделить существующую функциональность от будущих задач.
- [ ] Проверить ссылки и примеры документации после открытия PR.

## Этап 2. Тесты backend

- [ ] Проверить существующий `TeamupPlatformApplicationTests` и определить, что реально тестируется.
- [ ] Unit-тесты `AuthService`: успешная регистрация, дублирующий email, успешный вход, неверные credentials.
- [ ] Unit-тесты `UserService`: получение/обновление профиля и поиск.
- [ ] Unit-тесты `SkillService`: список навыков, создание навыка, обновление навыков, запрет изменения чужого профиля.
- [ ] Unit-тесты `ProjectService`: создание, чтение, фильтрация, обновление, удаление, членство и выход.
- [ ] Unit-тесты `ProjectApplicationService`: подача, статусы, принятие/отклонение, удаление и проверка прав.
- [ ] Unit-тесты `InvitationService`: создание, повторное приглашение, принятие/отклонение и права доступа.
- [ ] Unit-тесты `RecommendationService`: ранжирование, совпадение навыков и исключение пользователей без `lookingForTeam`.
- [ ] Unit-тесты `HackathonService`: CRUD, фильтры по формату и дате.
- [ ] Unit-тесты `MentorService`: CRUD и связи с навыками.
- [ ] Unit-тесты `AvatarService`: тип/пустота файла, сохранение и URL ответа.
- [ ] Добавить тесты контроллеров для основных HTTP-кодов и сериализации DTO.
- [ ] Добавить тесты Spring Security: отсутствие токена, неверный токен, разрешённые/запрещённые действия.
- [ ] Запустить `./mvnw test` и устранить ошибки.

## Этап 3. Frontend и интеграция

- [ ] Выполнить `npm run build` из `frontend/`.
- [ ] Выполнить `npm run lint` из `frontend/`.
- [ ] Проверить регистрацию, вход, logout и истечение/отсутствие JWT.
- [ ] Проверить профиль, загрузку аватара и сохранение навыков.
- [ ] Проверить создание/редактирование/удаление проекта.
- [ ] Проверить заявки, приглашения, вступление и выход из проекта.
- [ ] Проверить рекомендации и фильтры пользователей/проектов.
- [ ] Проверить каталоги хакатонов и наставников.

## Этап 4. Безопасность и данные

- [ ] Проверить права на каждую операцию с проектами, заявками, приглашениями, навыками, хакатонами и наставниками.
- [ ] Проверить `GET /api/invitations/status/user/{userId}` на раскрытие чужих данных.
- [ ] Убедиться, что секреты и пароли не хранятся в Git.
- [ ] Проверить необходимость ротации JWT secret, если он когда-либо публиковался.
- [ ] Проверить фактические FK/unique constraints в PostgreSQL.
- [ ] Разобраться с параллельными моделями членства: `Project.members` и `ProjectMember`.
- [ ] Спроектировать миграции схемы БД.
