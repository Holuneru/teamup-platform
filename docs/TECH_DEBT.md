# Технический долг TeamUp

Реестр известных технических долгов проекта. Этот файл — источник истины для долгов; `TASKS.md` содержит рабочие задачи и ссылается на ID отсюда.

## Правила ведения

- ID (`TD-01`, `TD-02`, ...) не переиспользуются. Закрытый долг удаляется из таблицы, но его ID больше не выдаётся другому пункту.
- Приоритеты: **высокий** — блокирует деплой или целостность данных; **средний** — создаёт риск регрессий или замедляет разработку; **низкий** — осознанно отложено, дискомфорт без потери данных.
- Долг считается закрытым, когда есть код/миграция и проверка (тест или подтверждённый ручной сценарий).
- Продуктовые идеи и будущие функции сюда не попадают. Для них — `ROADMAP.md` и `docs/plans/`.
- Файл обновляется в том же коммите, который закрывает или создаёт долг.

## Пояснения

### TD-01. Две системы управления схемой

`spring.jpa.hibernate.ddl-auto: update` создаёт и меняет таблицы автоматически, а Flyway применяет SQL из `db/migration`. Из-за этого нельзя однозначно сказать, какая схема получится на чистой базе. Дополнительно `V6__extend_notification_types.sql` и `V7__add_task_event_notification_types.sql` содержат одинаковый `ALTER TABLE`. Закрытие требует: выбрать один механизм (целевой — Flyway), описать полную схему миграциями и проверить её на чистой базе.

### TD-02. Две модели членства

`Project` хранит список участников, и одновременно существует сущность `ProjectMember`. Правила проекта запрещают менять обе модели одновременно без понимания, где какая используется. Перед закрытием нужно составить карту использования и свести к одной модели.

### TD-11. Загрузка файлов

`AvatarService` — единственная точка загрузки. Лимит размера фактически задаётся дефолтом Spring (`multipart`), а не конфигурацией проекта; ошибки валидации бросаются как `RuntimeException` и не дают отдельного кода ответа. При проектировании файлов проекта эти решения нужно принять осознанно, а не копировать текущее поведение.

### TD-12. Битые уведомления

Очистка при удалении проекта/задачи и при исключении участника возможна через `targetUrl`, без миграции, но признана низкоприоритетной: ущерб ограничен. Решение зафиксировано в истории обсуждения, код не менялся.

### TD-13. Опрос вместо WebSocket

Периодический опрос выбран сознательно; правила проекта не разрешают добавлять WebSocket в рамках стабилизации. Пересматривать только при подтверждённой нагрузке или требованиях к задержке.
